15. Seq2Seq & Attention

Machine translation with encoder–decoders, the bottleneck problem, and attention — with a full numeric example.

Part B · Neural NLP🎙 Neural NLP Lecture 6 (13 Nov)

In 30 seconds

  • Seq2seq = two RNNs. The encoder reads the source sentence into a context vector, and the decoder starts from that vector and generates the target sentence.
  • Almost any text-generation task fits this source → target mould: translation, summarisation, dialogue, code generation.
  • The bottleneck problem: squeezing a 100-word sentence into one vector loses information.
  • Attention: at each decoding step, compare the decoder state with every encoder state (dot products) → softmax → weights α → a weighted sum = a fresh context vector focused on the relevant words.
  • Attention also gives interpretability (heatmaps). Transformers go further: self-attention computed in parallel, plus positional encodings.

Machine translation with two RNNs

Encoder: ht = tanh(We xt + Ue ht−1)   c = hT   |   Decoder: s₀ = c,   st = tanh(Wd yt−1 + Ud st−1),   ŷt = softmax(V st)
The key trick

Both halves are ordinary RNNs. What makes the second one a decoder is that its first hidden state s₀ is initialised with the encoder's summary c. Unfold s₁ = tanh(Wdy₀ + Uds₀) and the source sentence's meaning flows into every generated word. Without that link, two separate RNNs couldn't translate anything.

Training: prepare (source, target) sentence pairs. Compute a cross-entropy loss Jt on each target word and sum. The whole system is optimised end to end: one loss, with back-propagation through decoder and encoder together. You can stack several layers (deep encoder–decoders; BERT-style models often have 12 layers). Either RNN can be bidirectional.

The bottleneck problem

Analogy: summarising a movie in one tweet

Ask someone to compress a 3-hour film into one sentence, then have someone else retell the full film from that sentence alone. Details vanish. The encoder squeezes a 100-word sentence into one fixed vector, and not every word deserves equal space, so important information gets lost.

Attention: let the decoder look back

Instead of relying on one summary, the decoder looks at all encoder hidden states at every step and decides which ones matter right now.

  1. Scores: dot product of the current decoder state with each encoder state: et,i = st · hi.
  2. Attention weights: αt = softmax(et). These are positive and sum to 1.
  3. Context vector: ct = Σi αt,i hi, a weighted average of encoder states.
  4. Use it: combine ct with st (e.g. concatenate [ct; st]) to predict the next word.
Intuition: translating "I like computer science"

When generating मुझे, the decoder compares its state with h(I), h(like), h(computer), h(science). Suppose the softmax gives α = [0.2, 0.7, 0.1, 0.0]. Then "like" (and "I") dominate the context vector for this step. At the next step the weights shift to "computer".

Worked numeric example (exam style)

Encoder states (2-D): h₁ = (2, 0), h₂ = (−1, 2), h₃ = (1, −1), h₄ = (0, 1). Decoder state s = (1, −2). Dot-product attention.

1. Scores ei = s · hi:

e₁ = 1·2 + (−2)·0 = 2   e₂ = −1 − 4 = −5   e₃ = 1 + 2 = 3   e₄ = 0 − 2 = −2

2. Softmax: exp values ≈ 7.389, 0.0067, 20.086, 0.135 (sum ≈ 27.617):

α ≈ [ 0.268, 0.0002, 0.727, 0.005 ]

3. Context vector c = Σ αi hi:

c ≈ 0.268·(2,0) + 0.0002·(−1,2) + 0.727·(1,−1) + 0.005·(0,1) ≈ (1.26, −0.72)

The decoder is mostly "looking at" h₃ (73%) and h₁ (27%).

Padding and masking. Sentences in a batch have different lengths, so we pad them with <PAD> tokens (plus <s>/</s> markers). A mask forces the attention on pad tokens to zero so the model never attends to them.

Attention as interpretability

Plot α as a heatmap: rows are generated words, columns are source words. In translation, "économique" lights up over "economic", "zone" over "zone". In summarisation, the headline word "terrorism" attends to "terrorism" in the article. In sentiment analysis, a "positive" label for "I am happy today" attends mostly to "happy". You can see why the model decided what it did.

Why RNNs gave way to transformers

  • Long-distance dependencies are hard to learn (vanishing gradients).
  • No parallelism: ht needs ht−1, so you can't compute all positions at once, and GPUs sit idle.
Transformers in two lines

Self-attention computes a query, key and value for every token and lets every token attend to every other token, all in parallel. But parallel processing loses word order, which an RNN gets for free by unfolding step by step. So transformers add positional encodings (originally sine/cosine; modern models use methods like rotary embeddings).

Greedy decoding (always taking the single most probable next word) was mentioned but skipped in class.

Exam tip (flagged as important)

Attention is a priority. Expect numerical questions: given encoder states and a decoder state, compute dot-product scores → softmax → context vector. Also explain the bottleneck problem, the role of s₀ = c, and why transformers need positional encoding. LSTMs won't be examined in detail. RNN + attention will.

Try it

Redo the numeric example with decoder state s = (0, 1). Which encoder state gets the most attention? (Scores: 0, 2, −1, 1, so h₂ wins with α ≈ 0.64.)

From the lecture slides

  • NMT as a conditional language model: the decoder is an LM (it predicts the next target word), and it's conditional because it also sees the source x: P(y|x) = Πt P(yt | y1…yt−1, x). Training needs a big parallel corpus (there's also work on unsupervised NMT and data augmentation).
  • Test-time behaviour: the decoder's argmax output is fed in as the next step's input ("il m'a entarté" → "he hit me with a pie <END>"). Example from the slides: "I like deep learning" → 我喜欢深度学习.
  • Multi-layer encoder–decoder (Sutskever et al. 2014; Luong et al. 2015): the hidden states of RNN layer i are the inputs to layer i+1 ("Die Proteste waren am Wochenende eskaliert" → "The protests escalated over the weekend").
  • Attention (Bahdanau et al., "Neural Machine Translation by Jointly Learning to Align and Translate", ICLR 2015): each decoder state sees a different, dynamic context that is a function of all encoder states. It's also used for summarisation (Rush et al., EMNLP 2015).
  • Issues with recurrent models: O(sequence length) steps that can't be parallelised, which "inhibits training on very large datasets".

Numericals

From class Exact slide problems

C1. "Try this problem": dot-product attention

Encoder h₁ = [2, 0], h₂ = [−1, 2], h₃ = [1, −1], h₄ = [0, 1]. Decoder (query) s = [1, −2].

Scores eᵢ = sᵀhᵢ: e₁ = (1)(2) + (−2)(0) = 2 · e₂ = (1)(−1) + (−2)(2) = −5 · e₃ = (1)(1) + (−2)(−1) = 3 · e₄ = (1)(0) + (−2)(1) = −2 → e = [2, −5, 3, −2]

Softmax αᵢ = exp(eᵢ)/Σexp(eⱼ): α = [0.2671, 0.0002, 0.7275, 0.0052]

Context c = Σ αᵢhᵢ = 0.2671[2, 0] + 0.0002[−1, 2] + 0.7275[1, −1] + 0.0052[0, 1]
c₁ = 2(0.2671) − 0.0002 + 0.7275 = 1.2615 · c₂ = 2(0.0002) − 0.7275 + 0.0052 = −0.7219 → c = [1.2615, −0.7219]. The third encoder state gets the highest weight.

P5. In C2, what changes if the attention is dot-product instead of additive?

Dot-product attention has no weights, so subtract 49,152: 32,212,992. (This needs the query and key sizes to match. Here 256 ≠ 128, which is one reason additive attention was used.)
